# 保密行政表：来源关系整理，不缩减模板能力

## 本轮问题与修复

基线 `941e92e` 的 BSU 第3块有三种叠加错误：完整行政表漏引默认公开
条款；纯外部审批/盖章义务挂了同一行政表的非空字段副本；重试另建
默认公开条款要求，又复制了全部表格和未关联的保密期限。

新增 `source_bound_administrative_copy_projection_v1` 只对完全可证明的
副本做关系整理，不禁止封面、行政字段或保密选项，也不改变角色 schema。

- 先重新计算并匹配当前响应的完整 validator 反馈，旧记录/选取部分错误无效。
- 对引用原文逐项验证 evidence、SHA-256、offset 和物理 location。
- 只保留唯一、有当前字段标签证据的可执行表。标题、默认公开段落和表格
  必须相邻；中间的外部行动只能来自默认公开段落同一证据。其他结构
  不被自动猜测，也不被宣称为不支持。
- 只补入唯一、来源编译明确的默认公开条款关系；不生成新属性或重分类。
- 待审批副本仅在所有已有属性被保留表包含、相对字段顺序相同且没有
  独有前置条件或身份时才移除。可执行副本须属性完全相同、所有来源边
  已由保留表覆盖。独有内容或冲突继续阻塞，不能删掉来通过。
- 保留表的属性、全部 clause reviews 和 pending obligations 不变。
  原始响应不修改，删除副本完整记录在当前运行绑定的审计里。
- 整个候选必须重新通过原有契约，再接受新的独立来源覆盖审查。
  这不验证导师同意、申请、批准或印章是否实际存在，不开启提交门禁。

同时修正了期限许可校验：必须逐个选项匹配对应标签、数值和单位。
一个选项有“可少于”证据不能替另一个选项提供许可。
