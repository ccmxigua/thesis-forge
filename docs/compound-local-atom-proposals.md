# Compound validator-bound primary proposals

`validator_bound_compound_atom_proposal_v1` is an opportunity for the primary
agent to propose a correction, not a deterministic interpretation of source
meaning or a compliance certificate. No school, clause ID or source literal is
hard-coded. It uses the existing ordinary attempt budget; it does not restart
or expand that budget.

Recompute the complete error bundle against the exact parent and current
source. Authenticate all named addresses and current source occurrences.
Only these diagnosed proposals can be copied from the immutable model retry:

- A mixed executable/external inventory missing one status may append atoms
  of that missing status. Existing atoms, IDs, order and payload are frozen.
  New quotes must bind uniquely to the current source, and routes must match
  pending human or proposed automatic responsibility. Neither a title nor an
  exact quotation proves that the new actor/action interpretation is correct.
- A covered atom with unknown/conflicted applicability may propose
  `applicable`; the code never supplies this value itself. Fresh independent
  review must substantiate the proposed scope.
- An invalid quotation may be replaced with the primary's uniquely bound
  literal quotation. The action, target, force and status remain unchanged;
  a literal subspan alone does not prove that it represents the whole duty.

The projected candidate starts from the parent. Unrequested reason, target,
requirement or other edits are excluded and individually audited, not silently
accepted. Any new reported conflict stops this projection. All local schema,
relation, coverage and source checks must pass together; incomplete, duplicate
or stale diagnostics and unsupported error combinations fail closed.

An unaccepted repair base may intentionally lack model provenance. Never
insert identity fields to make it appear fresh. The native coordinator instead
verifies persisted parent/raw bytes, canonical digest, complete unchanged
invocation fingerprints and deterministic replay of the full repair/error
state. It supplies a separate code-owned parent-binding proof. Without current
provenance or this verified coordinator proof, the projection is unavailable.

Acceptance still requires a fresh independent source-first review of the
complete candidate. Review rejection does not merge or publish it. Authorization
and audit explicitly retain `independent_review_required=true`,
`mechanical_equivalence_claimed=false` and `submission_ready=false`.

Regression coverage includes compound errors, exact field isolation, both mixed
inventory directions, stale/missing/duplicate feedback, conflicting proposals,
wrong source/quotes/IDs, and native mocked accept/reject runs with and without
model provenance. Captured BSU replay establishes local validation and drift
authorization only, not fresh provider review, DOCX or Word acceptance.
