# Bounded missing-requirement proposals

A primary retry for `missing_derived_requirement` is not permission to rewrite
the declaration quotation, existing requirements, atomic obligations or other
response fields. When the **entire** current parent error bundle consists of
that exact missing-edge error, the bridge can read the model's replacement as a
bounded addition proposal rather than accept all of it.

The projector recomputes and matches the complete validator records, parent
digest, current invocation fingerprints, unique clause/review identities and
exact current source spans. It extracts only new requirements whose edges are
contained in the named executable targets and whose evidence belongs to them.
Existing-ID proposals, duplicate additions, incomplete target coverage and
invalid role/property/source data fail closed. Mixed relation errors and other
simultaneous parent failures are not authorized by this rule.

Every old requirement and all other parent fields are retained verbatim.
Unrequested model changes remain in the immutable raw response and are recorded
as discarded paths with parent/proposal/projected hashes, accepted additions and
source bindings. Full contract validation is mandatory after constructing the
candidate. A new independent source-first review must assess the proposed
requirements; the projector does not establish semantic correctness or document
compliance, and submission readiness stays false.

Tests use generic source IDs and real validators. Native orchestration tests mock
provider responses and check both acceptance after a fresh review and rejection
without a merged output. Captured BSU responses are replayed separately offline;
neither is a final DOCX or Word acceptance claim.
