# Mixed inventory corrective review

A mixed executable/external proposal must account separately for the document
operation and every outstanding human action. Mentioning a document operation
in the rationale is not an inventory entry or proof of coverage.

When an independent result contains a source-valid, reference-valid partial
inventory with unique current primary IDs and status-consistent dispositions,
missing typed mappings and changed typed fields receive the existing bounded,
same-candidate corrective review. This is a rejection route, not acceptance,
a new primary-edit grant, automatic atom insertion or a new retry budget.

The primary inventory must itself be complete and typed, with both covered and
unverifiable states. Legacy/incomplete primary metadata, foreign or duplicate
IDs, unrelated references, wrong dispositions and invalid quotes cannot gain
this route. All acceptance checks still require a complete one-to-one mapping;
persistent interpretation disagreements remain blocking.

Captured parent responses, source-reference compilations and native partition
proofs are replayed before retaining any independently validated sibling.
Omitted atoms remain fresh review work. Only a new, fully validated response
can establish coverage; external actions stay pending and cannot authorize
submission. No school, clause ID or fixed declaration sentence selects this
behavior.

Regression tests cover omitted document/human duties with simultaneous typed
differences, unsafe mapping/reference/quote combinations, legacy primary data,
captured retry replay, sibling preservation and stale-source rejection.
Offline tests do not establish real BSU or DOCX/Word acceptance.
