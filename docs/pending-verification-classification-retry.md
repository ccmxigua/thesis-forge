# Pending external vs existing-content verification

A source-first independent review may identify an existing-thesis-content
verification duty while the primary classified that same duty as
`external_compliance`. The first observation is **rejected**, not silently
accepted as complete coverage. A bounded primary retry may propose only
`classification = requires_source_verification`.

## Authorization

- Both inventories must be nonempty, typed, one-to-one and exclusively pending.
- Each independent atom must select the exact current primary ID; actor,
  action, target, source quote, force, applicability and condition must match.
- No linked requirement, code-known local duty or pending authoring work may
  take this route. Mixed executable/external work keeps its separate protocol.
- The bridge reconstructs the raw source-reference response, packet and
  compilation, reproduces the rejection against the immutable candidate and
  binds the authorization to the current source/evidence, run and candidate.
- The grant retains the rejected result and primary-inventory hashes.
  Primary retry validation checks these bindings again. Only classification
  can change; original pending status, typed semantics, reasons, identities
  and the complete requirement graph remain unchanged.
- If the same independently identified pending inventory disagrees on a typed
  target/force/condition, it first takes the existing bounded same-candidate
  typed rereview. It receives **no** classification grant until every typed
  dimension agrees. Persistent semantic disagreement remains rejected.
- Ordinary contract validation and a new independent review are still required
  before acceptance. The proposal alone does not count as coverage.

No school, clause ID, exact phrase or lexical allowlist selects this route.
The independent reviewer owns the semantic distinction between checking
existing content and performing real-world actions. The preservation proof is
not evidence that this semantic interpretation is correct; actual approval
and signature duties must continue to be reported as external actions. Even
an erroneous manual-to-manual proposal cannot erase the duty, certify it or
authorize submission: every atom remains in the human queue and unverified.

## Regression evidence

Tests exercise the real contract validator, source-reference compiler,
persisted-artifact rejection replay, bridge grant and retry drift guard with
an offline reviewer. They reject omitted/duplicated duties, mismatched typed
dimensions, unrelated references, changed source hashes, linked executable
work and primary edits beyond classification. They also preserve the normal
external-action route. These offline checks do not replace a fresh BSU run
or DOCX/Word acceptance.
