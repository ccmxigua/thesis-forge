# Structural source inventory and generation consistency

Preserving a fixed template heading or literal is document work, distinct from
the truthfulness, signature or approval duties that may occur beside it. A
review rationale saying a linked requirement preserves a heading is not an
atomic source inventory. No school name, heading text or clause ID selects the
rule.

Generation now mirrors the existing nonempty acceptance boundary for a
non-informational check with `requires_requirement=true` and current linked
requirements: a `consistent` result needs an explicit inventory. The portable
first/remaining envelope carries this as a non-null first atom even where a
native adapter drops array `minItems`. Other diagnostic verdicts remain open.
The prompt explains structural preservation in both initial and bounded
corrective review.

This never synthesizes an obligation, quote, primary mapping or reference.
Primary classification and links are not semantic evidence. The reviewer must
independently confirm a source duty, retain unsupported interpretations or
uncertainty, and pass all existing source/schema/semantic checks. A descriptive
informational heading still permits an empty inventory; real-world assertions
remain pending rather than proven by declaration text.

Historical raw responses remain compilable as evidence and are still rejected
by the unchanged canonical semantic validator when their inventory is empty.
No old run is accepted, no extra provider attempt is granted, and fresh BSU,
document generation and Word acceptance remain separate validation gates.
